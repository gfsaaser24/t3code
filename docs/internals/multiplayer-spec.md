# Multiplayer spec: campfire collaboration on T3 Turbo

Status: draft for build. Date: 2026-09-13. Base: turbo tip `2bcf9daf1` (v0.0.52, upstream
`c0ebc882b` = v0.0.39-nightly.20260903.1273). Line numbers below were read at that tip; re-check
after the next upstream ingest.

Goal. Many Clerk users open one environment through the relay. Each person has a real name on the
server. People see who is here and who is typing. Each agent thread gets one team chat with
mentions, reactions, read markers, and an inbox. Works on hosted web, desktop, and mobile.

Source. Port of `astraly-labs/campfire` presence, side threads, and team inbox. We do not take
Google OIDC, the Codex provider host, the context assistant, Giphy, snooze, Tailscale flags, or
the Mac mini ops. Identity comes from what we already run: Clerk in the relay, Supabase Postgres
behind the relay, and the cloud mint proof the relay already sends to the local server.

## 0. What we found (facts the spec relies on)

- Relay `relayEnvironmentLinks` is keyed `(userId, environmentId)` and already has an index on
  `(environmentId, revokedAt)`. N users per environment is representable today. The only writer
  is `EnvironmentLinks.upsert`, reached only from `linkEnvironment`, which needs an
  environment-signed proof. So a teammate cannot get a row unless they pair the machine themself.
- Relay reads only `sub` from the Clerk JWT. No name, no email.
- Relay to server: `EnvironmentConnector.connect` signs a `t3-cloud-mint+jwt` with `sub` = Clerk
  userId and POSTs it to the environment. `cloudMintCredentialHandler`
  (`apps/server/src/cloud/http.ts:949`) verifies it, then requires `sub === CLOUD_LINKED_USER_ID`
  (`http.ts:992`) and issues a pairing link with hardcoded `subject: "cloud-connect"`
  (`http.ts:1017`). Those two lines are the whole identity blocker.
- `AuthenticatedSession` (`apps/server/src/auth/EnvironmentAuth.ts:64`) has `subject` but no
  display name. `ws.ts` never passes an actor into `orchestrationEngine.dispatch`
  (`ws.ts:485-491`, only `origin`). Upstream has no actor concept in contracts.
- Highest server migration is `047_ProjectionProjectIcon.ts`. Relay migrations are generated by
  Alchemy from `infra/relay/src/persistence/schema.ts` at deploy time.
- Seams that must not move: `pooled-subscription-frame` (client.ts), durable config resubscribe
  (session.ts), batched projection bootstrap (ProjectionPipeline.ts), VCS status semaphore, and
  the relay `ttlMemo` link caches (5 s memo; writes must pass `bypassMemo: true`).

## 1. Identity (relay + server)

### 1.1 Clerk claims to the relay

Add `email` and `name` to the Clerk JWT template used by `VITE_CLERK_JWT_TEMPLATE`
(`{{user.primary_email_address}}`, `{{user.full_name}}`). Relay change:

- `infra/relay/src/http/Api.ts`: `verifyClerkBearerToken` and `verifyClerkOAuthBearerToken`
  return `{ userId, email?, displayName? }`. Extend `RelayClientPrincipal`
  (`packages/contracts/src/relay.ts:568`) with optional `email`, `displayName`.
- Fallback when claims are missing: Clerk Backend API `GET /v1/users/:id` with
  `clerkSecretKey`, wrapped in a new `ttlMemo` (`infra/relay/src/turbo/ttlMemo.ts`), 10 min TTL.
  Never block a request on it. Missing name falls back to the email local part, then to `sub`.

### 1.2 Team membership in the relay

Schema (`infra/relay/src/persistence/schema.ts`):

- `relayEnvironmentLinks` adds `role text not null default 'owner'` (`owner` | `member`) and
  `invitedByUserId text`. Existing rows stay `owner`.
- New table `relayEnvironmentInvites`: `id`, `environmentId`, `environmentPublicKey`,
  `inviterUserId`, `inviteeEmail` (lowercased), `role`, `createdAt`, `expiresAt`, `acceptedAt`,
  `acceptedByUserId`, `revokedAt`. Index on `(inviteeEmail, revokedAt)`.

Routes (contracts in `packages/contracts/src/relay.ts`, handlers in `Api.ts`, `RelayClientGroup`):

- `POST /v1/client/environment-links/:environmentId/invites` `{ email, role }`. Owner only.
  Creates an invite. 7 day expiry.
- `GET /v1/client/environment-links/:environmentId/members`. Owner or member. Returns
  `[{ userId, displayName, email, role, joinedAt }]` plus pending invites for owners.
- `DELETE /v1/client/environment-links/:environmentId/members/:userId`. Owner only. Sets
  `revokedAt` on the member link. Also revokes their live relay sessions by rotating nothing:
  the local server rejects the next mint because the relay stops signing for that user.
- `GET /v1/client/invites`. Lists open invites for the caller's email.
- `POST /v1/client/invites/:id/accept`. Caller email must match. Inserts a
  `relayEnvironmentLinks` row copying `environmentLabel`, `environmentPublicKey`, endpoint URLs,
  `endpointProviderKind`, `managedTunnelsEnabled` from the owner row, with `role = 'member'`,
  `notificationsEnabled = false`, `liveActivitiesEnabled = false` (so APNs fan-out does not
  start pushing the owner's alerts to the teammate), `bypassMemo: true` on the write path.
- `listEnvironments` already filters on `userId`, so members see the environment at once.
  `unlinkEnvironment` by a member revokes only their row. By the owner it revokes every row.

Mint proof: `EnvironmentConnector.connect` adds `displayName`, `email`, and `role` claims to the
`t3-cloud-mint+jwt`. The relay only signs for users with a live link row, so the local server
can trust these.

Web app (hosted and desktop): Settings, Connections, environment card gets a "Team" section.
Owner: invite by email, list members, remove. Member: leave. State lives in
`packages/client-runtime/src/relay/managedRelayState.ts` next to `environmentsAtom`. Mobile:
read-only member list on the environment sheet.

### 1.3 Server accepts many users and names them

`apps/server/src/cloud/http.ts`:

- Replace the `sub === linkedCloudUserId` checks at `:874` and `:992` with: `sub` must be present
  and the relay signature must verify. The owner check is now the relay's job. Keep
  `CLOUD_LINKED_USER_ID` as the owner marker for unlink and status display.
- `createPairingLink` at `:1017` becomes
  `subject: "clerk:" + proof.sub`, `label: proof.displayName ?? proof.email ?? proof.sub`,
  `role: proof.role`.

`apps/server/src/auth/EnvironmentAuth.ts` and `auth/PairingGrantStore.ts`:

- `IssuedPairingLink`, the grant row, and `AuthenticatedSession` add optional `displayName`
  and `role`. They flow through `exchangeBootstrapCredentialForAccessToken` (`:732`) unchanged.
- `AuthClientSession` (`packages/contracts/src/auth.ts:242`) adds optional `displayName`,
  `role`. `listSessions` and `accessChanges` carry them. Mobile ignores unknown optional keys.

`apps/server/src/ws.ts`:

- Build `authenticatedActor` once per socket at `:467`:
  `{ kind: "client", subject: session.subject, displayName: session.displayName ?? subject,
sessionId: session.sessionId }`.
- `dispatchFromClient` (`:485`) passes `{ origin, actor }`. `OrchestrationEngine.dispatch`
  threads `actor` into `decideOrchestrationCommand`. Contracts add `OrchestrationEventActor`
  and an optional `actor` on `OrchestrationEventMetadata` (`orchestration.ts:1470`) so every
  event records who did it. Old events decode with `actor` absent.

Scopes: new methods get a scope in `RPC_REQUIRED_SCOPES`
(`apps/server/src/auth/RpcAuthorization.ts:100`). Members get `AuthStandardClientScopes` like
today. A later PR can narrow member scopes.

Local network and Tailscale pairing links: unchanged. Their subject stays the link subject. They
show up in presence as the pairing label. Team chat accepts them (see 3.2).

Tests: `cloud/http.test.ts` mint with a second `sub` succeeds and yields `clerk:<sub>`;
`EnvironmentAuth.test.ts` displayName round trip; relay `environmentInvites.test.ts` create,
accept, list, revoke, and "member cannot invite".

## 2. Presence

Contracts: new `packages/contracts/src/presence.ts`, copied from campfire verbatim
(`PresenceUser`, `PresenceEntry`, `PresenceSnapshot`, `PresenceHeartbeatInput`,
`PresenceHeartbeatResult`, `PRESENCE_WS_METHODS`). Register `presence.heartbeat` (request) and
`presence.subscribe` (`stream: true`, copy `WsSubscribeBackgroundPolicyRpc` at `rpc.ts:1198`)
in `WsRpcGroup`. Scope `environment:read` for both.

Server: new `apps/server/src/presence/Presence.ts`, copied from campfire. In-memory `Ref` plus
`PubSub.sliding(1)`. Capacity 64, presence TTL 15 s, typing TTL 4 s, sweep 1 s. Revision bumps
only when visible state changes, so idle rooms send nothing. Wire in `ws.ts`: per-socket
`presenceConnectionId`, `touch` on heartbeat, `drop` in the release step next to
`sessions.markDisconnected`. Add the layer in `server.ts`.

Client runtime: `packages/client-runtime/src/state/presence.ts`. Subscribe once per
environment through `subscribe` in `rpc/client.ts`. Presence snapshots are cumulative, so the tag
stays OUT of `NON_CUMULATIVE_SUBSCRIPTION_TAGS`. Heartbeat every 2 s while the tab is visible,
every 10 s hidden, carrying the focused `threadId` and a local typing flag with 3 s TTL.

Web: `apps/web/src/presence/PresenceAvatarStack.tsx` in `ChatHeader.tsx` left of the panel
toggles. Sidebar thread rows show a small dot count for viewers. Typing shows as "Gabe is
typing" under the composer.

Mobile: subscribe and show the avatar stack on the thread header. Heartbeat on foreground only.

Relay: no change. Traffic is two tiny messages per person every few seconds over the existing
tunnel.

Tests: `Presence.test.ts` from campfire (TTL, dedupe by session, capacity eviction, revision
stability). `ws` integration: two sockets, one heartbeat, both snapshots agree.

## 3. Side threads (team chat per agent thread)

### 3.1 Contracts

Copy the campfire side-thread slice into `packages/contracts/src/orchestration.ts`:
`SideThreadId`, `SideThreadMessageId`, `SideThreadAuthor`, `SideThreadAttachment`
(image only; the gif variant stays in the schema for forward compatibility, no picker),
`SideThreadMessageReaction`, `SideThreadReadMarker`, `SideThreadMessage`, `SideThread`,
`SideThreadShellMessagePreview`, `SideThreadShellSummary`. Add `sideThreads?: SideThread[]` to
`OrchestrationThread` and `teamDiscussion?: SideThreadShellSummary` to `OrchestrationThreadShell`
(`:563`). Six commands and six events, same names and payloads as campfire.

Copy `packages/shared/src/sideThread.ts` (`sideThreadIdForThread`, `isSideThreadIdForThread`,
`canonicalizeSideThreads`). One canonical discussion per thread, id `thread:<threadId>`.

### 3.2 Decider and projector

`decider.ts`: add the six cases. `requireSideThreadAuthor` accepts
`actor.kind === "client"` with a non-empty `subject`. No `google:` gate. Pairing-link users can
post; their subject is the link subject. Keep all campfire limits: 500 messages, 8 attachments,
20 mentions, https-only attachment URLs, quoted and reply ids must exist.

`projector.ts`: add the six folds. `sideThreads: []` at thread creation. Each fold runs
`canonicalizeSideThreads` then patches the canonical entry.

`ProjectionSnapshotQuery.ts`: add `mapSideThreadShellSummary` and call it where shell rows are
built (`:1712`, `:2103`). Add the six event names to the `event_type IN (...)` list at
`:1362` AND to `isThreadDetailEvent` in `ws.ts:309`. They must match or the client watermark
parks.

`ProjectionPipeline.ts`: no structural change. The new events flow through the existing batched
bootstrap. Do not touch `runProjectorBatch` or `deferredThreadShellSummaryIds`.

### 3.3 Persistence

- `048_ProjectionThreadSideThreads.ts`: `projection_threads.side_threads_json TEXT NOT NULL
DEFAULT '[]'`, guarded by `PRAGMA table_info`.
- `049_ProjectionCollaborationIdentity.ts`: `projection_projects.created_by_json TEXT`,
  `projection_threads.created_by_json TEXT`, `projection_thread_messages.author_json TEXT`.
- Register both in `Migrations.ts`. Campfire's 036 canonicalize migration is not needed; we
  start canonical.
- `Layers/ProjectionThreads.ts` adds `sideThreads: Schema.fromJsonString(Schema.Array(SideThread))`
  in `mapFields`; `ProjectionProjects.ts` and `ProjectionThreadMessages.ts` add the author
  columns. `thread.created` and `message.posted` payloads gain optional `createdBy` /
  `author` from the actor so old rows stay null.

### 3.4 Client runtime

`state/threadReducer.ts`: six cases mirroring the projector, plus `sideThreads: []` seed. Copy
`sideThreadReducer.test.ts`. `operations/commands.ts` and `state/threadCommands.ts` add
`createSideThread`, `postSideThreadMessage`, `reactToSideThreadMessage`,
`editSideThreadMessage`, `markSideThreadRead`, `archiveSideThread`.

The thread detail subscription already carries orchestration events one by one, so no new
subscription tag is needed. If a dedicated side-thread stream is added later it goes in
`NON_CUMULATIVE_SUBSCRIPTION_TAGS`.

### 3.5 Web

- `apps/web/src/sidethread/SideThreadDrawer.tsx`, `sideThreadUiStore.ts`,
  `QuoteOnSelection.tsx`, `TakeALookButton.tsx` from campfire. Drawer mounts in `ChatView.tsx`
  next to the right panel, gated on server threads. Toggle button in `ChatHeader.tsx` with an
  unread badge. Keybinding `mod+shift+t`. Command palette entry "Toggle team chat".
- Team roster comes from `accessChanges` sessions with `subject` present, deduped by subject,
  prefer `displayName`. File `apps/web/src/collaboration/team.ts` (campfire `googleTeam.ts`
  without the `google:` filter).
- Composer: mentions with `@` picker from the roster, image paste through the existing
  `attachmentUploadQueue`, quote selection from the agent transcript, reactions on hover.
- Reverse states: archive and unarchive (add `sidethread.unarchive` command and event; campfire
  has archive only), mark read on drawer open, mark unread from the inbox.

### 3.6 Mobile

Phase A read-only: thread screen gets a "Team" tab showing messages and a mark-read call.
Phase B: composer with text and mentions. Image attachments reuse the existing mobile upload
path. No presence typing on mobile.

## 4. Team inbox, mentions, notifications

- `apps/web/src/inbox/teamInbox.ts` from campfire: derive unread from `thread.teamDiscussion`
  (`latestMessage`, `latestMentions`, `readBy`) against the current subject. No server state.
- Sidebar section "Team inbox" (`sidebar/TeamInboxNav.tsx`), route `_chat.inbox.tsx`. Rows:
  thread title, last author, preview, mention badge. Click opens the thread with the drawer open.
- Browser `Notification` on new mention when the tab is hidden
  (`notifications/teamInboxNotifications.ts`). Desktop: forward through the existing Electron
  notification IPC. Mobile: add `sidethread.message-posted` with a mention of the device user to
  the relay `AgentActivityPublisher` allowlist so APNs fires. That is the only relay touch in
  this phase, and it respects the member row's `notificationsEnabled`.

PR into `gfsaaser24/t3code`, CodeRabbit on each.

cloud http; orchestration + persistence; client-runtime + web; mobile. Main thread integrates,
runs seam verify, builds.

## 7. Out of scope, on purpose

Google OIDC on the server. Per-user permissions or isolation (same trust model as campfire: a
member is root on the machine). Giphy. Context assistant. Codex provider host. Snooze. Tailscale
Serve flags. Multi-owner transfer.
